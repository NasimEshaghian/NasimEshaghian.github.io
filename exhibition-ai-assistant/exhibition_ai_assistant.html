Exhibition AI Assistant

An Intelligent RAG-Powered Exhibition Concierge

An AI-powered conversational assistant designed to help exhibition visitors discover relevant booths, explore events, navigate exhibition halls, and create personalized visiting plans.

n8n Ollama Qwen (qwen3:4b-instruct) Nomic Embeddings Supabase Vector Search Google Drive LangChain Nodes Webhooks HTML / CSS / JS

Case Study Scope

Built from exhibition_ai_assistant_portfolio.json, exhibition_demo_booking.json, and exhibition_workflow_architecture.mmd, this page documents how JSON exhibition records are ingested into a Supabase vector store (mcp_rag) and served through an anonymous session-based Persian chat workflow with an isolated sandbox booking sub-workflow.

Project Overview

Exhibition visitors need fast, structured answers about exhibitors, hall navigation, and schedules without sifting through disconnected JSON files or registering personal accounts.

Problem

Exhibition information spans multiple datasets—booth locations, hall access paths and maps, general logistics, and event schedules—making manual lookup slow and prone to mixed or ungrounded answers when handled by an unguided model.

Objectives

  • Separate knowledge ingestion from live visitor chat traffic.
  • Ground Persian responses in retrieved vector records with metadata tagging.
  • Enforce single-category responses, accurate booth/hall filtering, and separate hall maps.
  • Support anonymous session memory and isolate event booking in a sandbox sub-workflow.

Target Users

  • Exhibition Visitors: Finding booths by interest, looking up exact booth numbers and halls, checking access paths and hall maps, and browsing events.
  • Technical Reviewers: Auditing workflow orchestration, RAG retrieval, anonymous session handling, and sandbox isolation.

Key Capabilities

  • Automated JSON ingestion from Google Drive into Supabase (mcp_rag).
  • Anonymous session-keyed buffer memory via POST /exhibition-chat.
  • Persian AI Agent orchestration using qwen3:4b-instruct and nomic-embed-text:latest.
  • Standalone sandbox booking sub-workflow (exhibition_demo_booking.json) writing to demo_bookings.

How It Works

Stage-by-stage breakdown of the portfolio workflow architecture and its corresponding n8n nodes.

01

Google Drive JSON Sources

Scheduled triggers monitor designated Google Drive files for booth directories, general exhibition logistics, and event schedules so knowledge updates occur independently of visitor chat traffic.

n8n Nodes: Booths Drive Trigger, General Info Drive Trigger, Events Drive Trigger
02

Download and Extraction

Each triggered branch downloads the source file from Google Drive and parses its JSON content into structured n8n items for downstream processing.

n8n Nodes: Download Booths JSON, Extract Booths JSON, Download General Info JSON, Extract General Info JSON, Download Events JSON, Extract Events JSON
03

Data Normalization and Metadata Tagging

Code nodes clean missing or inconsistent fields, build readable Persian text payloads, and attach category tags (booth_info, general_info, events) plus structured attributes such as hall, booth number, access path, map URL, and event schedule fields.

n8n Nodes: Normalize Booths & Metadata, Normalize General Info & Metadata, Normalize Events & Metadata
04

Default Data Loader

Prepares normalized document content and maps 16 metadata fields into LangChain document objects for vector store insertion.

n8n Nodes: Default Data Loader
05

Nomic Embeddings through Ollama

Generates dense vector representations via Ollama using nomic-embed-text:latest for both document ingestion and runtime similarity queries.

n8n Nodes: Nomic Embeddings (Ollama)
06

Supabase Vector Storage (mcp_rag)

Inserts embedded documents and metadata into the mcp_rag table in Supabase configured with the match_documents retrieval function.

n8n Nodes: Supabase Vector Store (Ingest)
07

Visitor Chat Webhook (POST /exhibition-chat)

Receives incoming HTTP POST requests from the chat interface containing a visitor message and optional session identifier.

n8n Nodes: Visitor Chat Webhook
08

Anonymous Session Normalization and Validation

Normalizes or generates an anonymous sessionId without requiring phone numbers or user accounts, trims message text, and blocks empty messages with a 400 JSON response.

n8n Nodes: Normalize Anonymous Session, Validate Chat Input, Respond Validation Error
09

Session-Based Memory

Maintains recent conversational context per anonymous sessionId so follow-up questions about booth paths, maps, or event selection stay coherent across turns.

n8n Nodes: Anonymous Session Memory (@n8n/n8n-nodes-langchain.memoryBufferWindow)
10

Qwen Chat Model

Provides language generation through Ollama using qwen3:4b-instruct configured for deterministic/low-variance Persian responses.

n8n Nodes: Qwen Chat Model (Ollama)
11

Exhibition AI Agent

Coordinates retrieval, session memory, and sandbox booking tools while enforcing Persian replies, grounding in retrieved knowledge, single-category-per-message formatting, exact booth/hall filtering, and separate hall-map display.

n8n Nodes: Exhibition AI Agent
12

Knowledge Retrieval Tool

Exposes mcp_rag as a vector retrieval tool to the agent (topK: 10) backed by Nomic Embeddings (Ollama).

n8n Nodes: Knowledge Base Retrieval Tool
13

JSON Response and Error Handling

Returns structured JSON ({ ok, mode, sessionId, reply }) on success or routes agent errors to a fallback JSON response (HTTP 500) instead of leaving the webhook hanging.

n8n Nodes: Respond Chat Success, Respond Agent Error
14

Sandbox-Only Booking Sub-Workflow

Invoked by the agent's booking tool when a visitor supplies required booking fields for a demo reservation; validates inputs, enforces booking_mode = "sandbox", generates a DEMO-... ID, and stores simulated records in demo_bookings.

n8n Nodes: Sandbox Demo Booking Tool (main workflow) → Sub-Workflow Trigger, Validate & Build Sandbox Record, Check Required Fields, Save Sandbox Demo Booking, Format Sandbox Confirmation, Format Validation Error (exhibition_demo_booking.json)

Technology Stack

Role of each technology present in the validated portfolio workflow and case study page.

  • n8n: Orchestrates scheduled ingestion triggers, webhook endpoints, JavaScript transformation nodes, error routing, and sub-workflow calls.
  • Ollama: Hosts local/self-hosted model inference for both chat generation and text embeddings.
  • Qwen (qwen3:4b-instruct): Powers the chat language model connected to the Exhibition AI Agent.
  • Nomic Embeddings (nomic-embed-text:latest): Generates vector embeddings during ingestion and retrieval.
  • Supabase & Vector Search: Stores vector documents in mcp_rag (via match_documents) and sandbox booking records in demo_bookings.
  • Google Drive: Source repository for exhibition JSON files (booths, general info, and events).
  • LangChain Components (in n8n): Provide the AI Agent, Buffer Window Memory, Default Data Loader, and Supabase Vector Store tool nodes.
  • Webhooks: Expose POST /exhibition-chat to accept visitor messages and return JSON responses.
  • HTML / CSS / JavaScript: Implements this standalone case study page, interactive architecture viewer, and local video player.

Technical Implementation

Core data contracts and orchestration mechanisms across the ingestion, retrieval, session, webhook, and sub-workflow layers.

RAG, Metadata & Vector Retrieval

Ingestion nodes normalize booth, general info, and event JSON records into content strings and metadata objects tagged with type (booth_info, general_info, events) plus filterable attributes (hall, booth_number, access_path, map_url, event_id, start_date, start_time, end_time). At query time, Knowledge Base Retrieval Tool queries mcp_rag with topK: 10 using embeddings from Nomic Embeddings (Ollama).

Session Memory, Webhooks & AI Agent

Normalize Anonymous Session extracts or creates an anonymous sessionId, Validate Chat Input rejects empty inputs with HTTP 400, and Anonymous Session Memory scopes conversation history by that sessionId. Exhibition AI Agent orchestrates Qwen Chat Model (Ollama) and its tools, returning structured JSON via Respond Chat Success or Respond Agent Error.

Sandbox & Privacy Notice

This portfolio demonstration uses an independent sandbox environment. Booking operations are simulated and do not create real exhibition reservations. Company-specific production systems, credentials, and private data are not included.

  • Anonymous Sessions: Visitors use session-keyed chat without phone number registration or personal authentication.
  • Simulated Booking Only: Event reservations enforce booking_mode = "sandbox", assign a DEMO-... identifier, and write solely to the demo_bookings table.
  • No Live Availability Claimed: This static case study page does not imply a live, publicly hosted chatbot endpoint unless configured and running on your own n8n and Ollama instance.

Outcomes & Engineering Learnings

  • Eliminated Workflow Duplication: Consolidated redundant agents, duplicate ingestion chains, and conflicting webhook definitions into a single maintainable workflow graph.
  • Enforced Clean Data & Sandbox Boundaries: Removed hardcoded visitor identifiers and isolated demo booking logic into a dedicated sub-workflow with explicit field validation and error fallbacks.
  • Portable Portfolio Packaging: Structured workflow JSONs with clear configuration placeholders and documented external dependencies (n8n credentials, Supabase tables/RPC, and Ollama models) for reproducible setup.
