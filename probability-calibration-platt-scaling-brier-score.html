Can We Trust an AI That Says There Is an 80% Chance?

Why a model’s confidence score is not automatically a trustworthy probability—and how Platt Scaling, reliability diagrams, and the Brier Score help us check it.

Learning Journal6 min readEnglish + فارسی

Imagine watching the evening weather report. The forecaster says, “There is an 80% chance of rain tomorrow.” That number has a useful meaning: across many comparable forecasts made at 80%, rain should occur about 80% of the time.

Now imagine a water-quality dashboard displays: “Spike risk: 0.80.” A person may naturally read that as an 80% chance of a spike. But a model’s numerical output is not automatically a well-calibrated probability. It needs to be checked against what actually happens.

An 80% prediction should mean something

A probability forecast is calibrated when predictions made with a particular probability match the observed frequency over many cases. If a system issues many 80% forecasts, roughly 80% of those events should occur, allowing for sampling uncertainty.

Calibration is different from discrimination. A model may rank high-risk cases above low-risk cases very well, yet still give probability values that are systematically too high or too low. Ranking answers “which case is riskier?” Calibration answers “do the numbers match real frequencies?” Both can matter.

Scores are not automatically probabilities

Some classifiers produce a decision score or margin. Others, including common boosted-tree implementations, can expose outputs through a probability interface such as predict_proba. That interface is useful, but it does not guarantee that a score of 0.80 corresponds to an 80% event frequency on new data.

Class weighting can make this distinction especially important. When training gives extra weight to rare positive examples—for example, through a parameter such as scale_pos_weight—the model is encouraged to pay more attention to that class. Its ranking may improve, but the resulting probabilities may need a separate calibration check.

Platt Scaling: a small post-processing layer

In 1999, John Platt described a practical method for mapping a classifier’s score to a probability using a logistic sigmoid. Instead of rebuilding the original classifier, we keep it fixed and learn two parameters, A and B, on a separate calibration dataset:

P(y = 1 | f) = 1 / (1 + exp(A · f + B))

Here, f is the model score. The learned sigmoid bends and scales the score so that its output better matches observed event frequencies. Platt introduced this method in the context of support vector machines; it is also used as a post-hoc calibration approach for other classifiers when the score and validation design are appropriate.

The calibration layer does not make the underlying model more knowledgeable. It adjusts how its scores are translated into probabilities. That is a different task from improving the model’s ability to distinguish event cases from non-event cases.

How to fit the calibration layer safely

The calibration data must be separate from the data used to fit the original model. If we train the classifier and fit the sigmoid on the same examples, we can obtain an overly optimistic picture of how well the probabilities will behave on new cases.

For time-series problems, the split must also respect time. A practical design is to train the model on an earlier period, fit calibration on a later but still historical period, and evaluate the complete pipeline on a final untouched period. Time-aware cross-validation can be useful when the dataset is large enough.

Platt’s original method also used smoothed target values to avoid extreme fits when one class is scarce. This is a reminder that a small calibration set with very few positive events can make any calibration curve unstable.

Another option is isotonic regression, a more flexible, non-parametric mapping. Flexibility can be helpful with enough calibration data, but it can overfit when the number of events is small. A two-parameter sigmoid is simpler; it is not automatically better in every dataset. The choice should be made using validation that reflects the intended use.

Reliability diagrams and the Brier Score

Reliability diagrams

A reliability diagram groups predictions into probability bins. For each bin, it compares the average predicted probability with the fraction of cases in which the event actually occurred. A perfectly calibrated model would lie on the 45-degree diagonal: predictions around 0.70 would correspond to an observed frequency around 70%.

If points lie below the diagonal, the model is often overpredicting risk in those bins. If they lie above it, the model is often underpredicting risk. The number of bins and the number of observations in each one matter; a curve based on only a handful of rare events can look more certain than it really is.

The Brier Score

Glenn W. Brier introduced a score for probabilistic forecasts in 1950. For a binary event, the Brier Score is the mean squared difference between each predicted probability and the observed outcome:

BS = (1 / N) · Σ (pt − ot)²

Here, pt is the predicted probability and ot is 1 when the event occurs and 0 when it does not. The score is 0 for a set of perfect forecasts, and lower values indicate better overall probabilistic accuracy.

One nuance is worth keeping: the Brier Score is not a pure calibration measure. It reflects more than one aspect of probabilistic forecast quality, including calibration and the ability to separate events from non-events. That is why it is useful to read it alongside a reliability diagram and discrimination metrics rather than alone.

What I learned

It is tempting to call predict_proba() and trust every decimal it returns. But a probability is a promise about long-run frequencies. It should be checked, especially after changing class weights or decision costs. A reliable risk dashboard needs both a useful ranking and probability estimates that have been tested on data the model did not train on.

The main takeaway

A model’s confidence score is not automatically a trustworthy probability. Platt Scaling can map model scores to better-calibrated probabilities, while reliability diagrams and the Brier Score help evaluate whether those forecasts agree with observed outcomes.

حالا به زبون خودمون

وقتی مجری هواشناسی می‌گه «فردا ۸۰ درصد احتمال بارندگی هست»، ما یه برداشت مشخص داریم: اگه صد بار توی شرایط مشابه چنین پیش‌بینی‌ای انجام بشه، انتظار داریم تقریباً توی ۸۰ بارش بارون بیاد.

حالا فرض کن داشبورد هوش مصنوعی می‌گه «احتمال جهش کدورت: ۰.۸۰». آیا واقعاً باید به این عدد اعتماد کنیم؟ نه لزوماً! ممکنه مدل فقط یه امتیاز بالا تولید کرده باشه یا خروجی احتمال‌مانندش با واقعیت هماهنگ نباشه. به این موضوع می‌گیم Probability Calibration.

جان پلات در سال ۱۹۹۹ روشی معرفی کرد که به اسم Platt Scaling شناخته می‌شه. ایده‌اش اینه که مدل اصلی رو دوباره آموزش ندیم؛ خروجی مدل رو به یه تابع سیگموئید می‌دیم و دو پارامترش رو با داده‌ای جدا از داده‌ی آموزش تنظیم می‌کنیم تا خروجی بهتر با فراوانی واقعی اتفاق‌ها جور دربیاد.

اما حواسمون باشه: داده‌ی کالیبراسیون نباید همون داده‌ای باشه که مدل باهاش آموزش دیده. توی مسئله‌های زمانی هم باید ترتیب تاریخ‌ها حفظ بشه. مثلاً داده‌ی قدیمی‌تر برای آموزش و یک بازه‌ی بعدی برای کالیبراسیون و ارزیابی نهایی استفاده بشه.

از کجا بفهمیم کالیبراسیون خوبه؟ دو ابزار مهم داریم:

  1. Reliability Diagram: پیش‌بینی‌ها رو گروه‌بندی می‌کنیم و احتمال متوسط رو با تعداد واقعی رخدادها مقایسه می‌کنیم. هرچی نقاط به خط مورب ۴۵ درجه نزدیک‌تر باشن، کالیبراسیون بهتره.
  2. Brier Score: میانگین مربع اختلاف احتمال پیش‌بینی‌شده با نتیجه‌ی واقعی (صفر یا یک) رو حساب می‌کنه. هرچی کمتر باشه، کیفیت کلی پیش‌بینی احتمالاتی بهتره؛ ولی این معیار فقط کالیبراسیون رو اندازه نمی‌گیره.

یه روش دیگه به اسم Isotonic Regression هم وجود داره که انعطاف‌پذیرتره، اما وقتی تعداد رخدادهای کمیاب خیلی کم باشه ممکنه بیش‌ازحد به داده‌ی اعتبارسنجی بچسبه. پس انتخاب روش باید با توجه به تعداد داده و اعتبارسنجی درست انجام بشه.

چیزی که من از این موضوع یاد گرفتم اینه که هر عددی که با علامت درصد یا احتمال از مدل بیرون میاد، الزاماً قابل اعتماد نیست. مدل باید ثابت کنه که وقتی می‌گه ۸۰ درصد، در شرایط مشابه واقعاً نزدیک به ۸۰ درصد مواقع درست پیش‌بینی می‌کنه.
