What Are XGBoost and SHAP?

Why ensembles of small decision trees can work well on structured data—and how game theory helps explain what moved a prediction.

Learning Journal6 min readEnglish + فارسی

If you read papers about machine learning for environmental systems, two names appear again and again: XGBoost and SHAP. They solve different problems. XGBoost is a prediction algorithm; SHAP is a way to explain how a model arrived at a particular prediction.

Together, they are useful when a dataset is made of rows and columns—such as weather measurements, sensor readings, or operational records—and when people need more than a final number. They want to understand which information influenced it.

Why combine many small trees?

A decision tree is like a flowchart. It asks a series of questions about the input: Was rainfall high? Was the soil already wet? Was the wind strong? At the end, it returns a prediction.

A single tree is easy to understand, but it can be unstable. A small change in the training data may produce a different set of branches. A very deep tree can also memorize the training examples instead of learning patterns that generalize.

Random Forest and Gradient Boosting both combine many trees, but they do it differently. Random Forest generally builds trees independently and combines their outputs. Gradient Boosting builds an additive model in stages: each new tree is trained to improve the errors or loss left by the current ensemble.

How gradient boosting learns

Imagine the first tree makes a rough prediction. It may be too high for some observations and too low for others. The next tree is not asked to start from scratch; it is trained to make an update that reduces the remaining loss. Later trees add more small corrections.

The final prediction is the sum of the baseline and the contributions from the sequence of trees. Each tree usually makes a relatively small adjustment. The learning rate controls how much each new tree contributes, while the number and depth of trees control the model’s complexity.

This is the intuition behind gradient boosting. In practice, the trees are fitted using gradients of a chosen loss function, so the method can be used for different tasks, including regression and classification.

What XGBoost adds

XGBoost is a scalable implementation of tree boosting introduced by Tianqi Chen and Carlos Guestrin. It adds engineering and modelling techniques designed to make training efficient and help control overfitting. These include regularization, efficient handling of sparse data and missing values, and systems-level optimizations.

Regularization matters because a model that is too complex can fit noise. Parameters such as tree depth, learning rate, number of trees, and regularization strength influence the balance between fitting the training data and generalizing to new observations.

Why use it on a small environmental dataset? Structured data with a moderate number of observations and a mixture of numerical features can be a good setting for boosted trees. Deep neural networks can also work, but with limited data they may need careful architecture choices and regularization. No algorithm wins automatically: models should be compared with a validation design that matches the real prediction task.

SHAP: explaining a prediction with game theory

Even a useful model can feel like a black box. Suppose a model predicts elevated risk for a future period. A person reviewing that output may ask: which inputs pushed the prediction upward, and which ones pulled it downward?

SHAP stands for SHapley Additive exPlanations. It is based on Shapley values from cooperative game theory. In a cooperative game, several players contribute to a shared outcome. Shapley values provide a principled way to assign credit to each player based on its contribution across possible groups of players.

For a machine-learning prediction, the “players” are the input features. SHAP assigns each feature a contribution relative to a baseline prediction. In a common additive explanation, the baseline plus all feature contributions equals the model output in the selected explanation space.

Model output = baseline value + Σ SHAP value for each feature

For tree-based models, TreeSHAP can calculate these feature contributions efficiently under its defined assumptions. The explanation can be shown for one individual prediction or summarized across many observations.

Reading feature contributions

In a typical SHAP force or waterfall plot, features that push the model output higher appear on one side, often in red; features that push it lower appear on the other, often in blue. The color convention depends on the plotting style, but the central idea is the same: contributions can move the prediction away from its baseline in different directions.

For an illustrative water-quality example, strong recent rainfall, wet soil, or wind-related features might push a model’s predicted risk upward. Other conditions might pull it downward. SHAP helps show which recorded inputs the model used most for that particular estimate.

A global SHAP summary can show which features tend to have larger contributions across a dataset. A local SHAP explanation focuses on one prediction. These answer different questions: “What matters to the model overall?” and “What moved this particular result?”

What SHAP cannot tell us

This is the most important caution: SHAP explains the model, not the physical world. A feature with a large SHAP value is influential in the model’s prediction, but that does not prove the feature caused the outcome.

A model may rely on a proxy variable, a correlated sensor, or a pattern that exists only because of the way the data were collected. For example, an operational set point might correlate with a treatment outcome because operators change it when conditions become difficult. The set point may help predict the outcome without being the underlying physical cause.

Research on chlorine residual prediction has shown why this distinction matters: feature-attribution methods can expose when a model relies heavily on variables that are not direct physical drivers. Removing such shortcuts may reduce a headline metric while making the model more aligned with the scientific question. The correct response is not to trust or reject SHAP blindly, but to combine it with domain knowledge, data checks, and carefully designed experiments.

SHAP values can also depend on how feature dependence is handled and which output scale is being explained. They are explanations under a modelling setup—not a substitute for causal analysis.

What I learned

Model performance and model explanation answer different questions. A strong test score tells us how well a model performed on an evaluation set. SHAP helps us inspect the patterns the model used. Sometimes those patterns are physically plausible; sometimes they reveal shortcuts that deserve investigation.

The main takeaway

XGBoost builds a prediction by combining many small trees that improve the model in stages. SHAP helps explain how individual features move a particular prediction—but feature contribution is not proof of causation.

حالا به زبون خودمون

اگه توی پروژه‌های هوش مصنوعیِ حوزه‌ی آب گشته باشی، احتمالاً به دو اسم زیاد برخوردی: XGBoost و SHAP. اولی یه الگوریتم پیش‌بینیه و دومی کمک می‌کنه بفهمیم مدل چرا به یه نتیجه رسیده.

برای فهمیدن XGBoost، اول یه درخت تصمیم رو تصور کن؛ همون فلوچارت سؤال‌های بله و خیر. مثلاً بارندگی زیاد بوده؟ خاک خیس بوده؟ باد شدید بوده؟ درخت با جواب این سؤال‌ها یه پیش‌بینی می‌سازه. اما یه درخت تنها ممکنه اشتباه کنه یا داده‌های آموزشی رو بیش‌ازحد حفظ کنه.

در Gradient Boosting، درخت‌ها پشت سر هم ساخته می‌شن. درخت اول یه حدس اولیه می‌زنه. درخت بعدی سعی می‌کنه خطا یا بخشی از خطای باقی‌مونده رو کم کنه. درخت‌های بعدی هم اصلاح‌های کوچیک دیگه‌ای اضافه می‌کنن. در نهایت پیش‌بینی از جمع این اصلاح‌ها ساخته می‌شه.

XGBoost نسخه‌ای سریع و مهندسی‌شده از این ایده‌ست که ابزارهایی مثل Regularization برای کنترل پیچیدگی مدل و روش‌هایی برای مدیریت داده‌های ناقص و محاسبات کارآمد داره. برای داده‌های جدولی و نسبتاً کوچک می‌تونه انتخاب خیلی خوبی باشه؛ البته هیچ الگوریتمی همیشه برنده نیست و باید با روش ارزیابی درست مقایسه بشه.

اما اگه مدل به اپراتور بگه «ریسک بالاست»، اپراتور حق داره بپرسه: «چرا؟» اینجاست که SHAP وارد می‌شه. اسمش از مفهوم Shapley Value در نظریه‌ی بازی‌ها میاد. فرض کن چند بازیکن با هم یه نتیجه ساختن؛ SHAP سعی می‌کنه سهم هر بازیکن رو منصفانه مشخص کنه. توی مدل، این بازیکن‌ها همون ویژگی‌های ورودی هستن.

در نمودار SHAP می‌تونیم ببینیم مثلاً بارندگی یا رطوبت خاک چقدر پیش‌بینی رو به سمت بالا هل داده و چه ویژگی‌هایی اون رو پایین آورده. این توضیح می‌ده مدل از چه اطلاعاتی استفاده کرده، نه اینکه حتماً چه چیزی در دنیای واقعی علت اون اتفاق بوده.

این تفاوت خیلی مهمه. ممکنه یه متغیر فقط با نتیجه همبستگی داشته باشه؛ مثلاً اپراتورها وقتی شرایط سخت می‌شه یه تنظیم خاص رو تغییر بدن. مدل از اون تنظیم برای پیش‌بینی استفاده می‌کنه، ولی این به معنی علت بودن اون متغیر نیست. پس SHAP رو باید کنار دانش مهندسی، بررسی کیفیت داده و تحلیل علمی استفاده کرد.

چیزی که من از کنار هم گذاشتن XGBoost و SHAP یاد گرفتم اینه که فقط خوب پیش‌بینی کردن کافی نیست. باید بررسی کنیم مدل بر اساس چه الگویی پیش‌بینی کرده و آیا اون الگو از نظر فیزیکی و مهندسی قابل دفاع هست یا نه.
